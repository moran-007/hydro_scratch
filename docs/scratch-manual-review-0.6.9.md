# Scratch 手动测评待处理队列说明

适用版本：`hydro-plugin-scratch 0.6.9+`

## 1. 功能说明

Scratch 手动测评题提交后会同时进入：

- Scratch 域级待批改队列：`/scratch/review`
- Hydro 原生测评记录中的“待处理”筛选

老师不需要先进入某一道题目才能找到待评分作品。域级队列默认显示当前域内所有 Scratch 题目的待评分提交，也可以按题目进一步筛选。

## 2. 入口

在启用 Scratch 插件的域中，具备题目编辑权限的老师可以从导航或域管理区域打开“Scratch 批改”。

也可以直接访问：

```text
/d/<域ID>/scratch/review
```

例如：

```text
http://moran007.top/d/scratch/scratch/review
```

单题提交列表仍保留“全部待批改”按钮，用于跳转到域级队列。

## 3. 筛选方式

域级队列支持：

- 按题号或题目名称筛选。
- 按比赛或作业名称筛选。
- 按普通题目、比赛、作业来源筛选。
- 按待评分、已评分或全部状态筛选。

默认状态为“待评分”，用于老师日常集中处理。

## 4. Hydro 原生待处理记录

从 `0.6.9` 开始，新提交的手动测评题会使用 Hydro 的 Waiting 状态保存，但不会加入自动判题任务队列。

因此老师在 Hydro 测评记录页面选择“待处理”时，可以直接看到这些 Scratch 提交。完成手动评分后，插件会继续通过 Hydro 成绩同步逻辑更新题目、训练、比赛或作业中的成绩。

旧版本已经生成的待评分 Scratch 记录可能仍使用旧状态。它们会继续出现在 Scratch 域级待批改队列中，不会因为升级而丢失。

## 5. 权限与域范围

- 队列只显示当前域中的 Scratch 提交。
- 队列只显示当前老师有权评分的题目提交。
- 未在 `enabledDomains` 中启用的域不会显示“Scratch 批改”入口，直接访问队列也会被阻止。
- 系统管理员或具备全域题目编辑权限的老师可以集中处理当前域内全部 Scratch 待评分提交。

## 6. 验证步骤

1. 使用学生账号进入一道人工作评分的 Scratch 题目并提交作品。
2. 确认学生端显示“待测评”。
3. 使用老师账号打开 `/d/<域ID>/scratch/review`。
4. 确认无需先进入题目即可看到该提交。
5. 在队列中按题号或题目名称筛选，确认仍能找到该提交。
6. 打开 Hydro 测评记录并筛选“待处理”，确认能看到该提交。
7. 完成手动评分，确认提交从默认待评分队列中消失，并在已评分筛选中出现。
8. 如果提交来自比赛、作业或训练，确认对应位置的成绩同步更新。

## 7. 注意事项

- 域级队列用于集中批改，不替代单题提交列表。
- 自动测评已经完成的提交不会出现在默认“待评分”列表中，但可以切换到“已评分”或“全部”查看。
- 自动测评配置错误而转入人工处理的提交也会进入待处理状态。
